# AI-Native 3D CAD — Research Synthesis & Build Plan

## Context
The project folder was empty, so this is a new build. The goal is the first AI-native, cross-platform 3D CAD app:
- Fusion, SolidWorks and Shapr3D-class parametric modeling.
- Blender-style freeform modeling at CAD precision.
- An in-app agent that builds sketches, parts, assemblies and drawings through the app's own tools, with professional engineering guidance.
- Humans can model by hand or edit anything the agent made.

**Owner decisions (2026-09-23):**
- **Roles.** The owner is the product owner. AI coding agents write, review and debug all code. Languages are chosen by purpose, and mixing them is fine.
- **Platforms.** Desktop first (macOS, Windows, Linux), then web, then iPad.
- **First users.** Makers, 3D printing and CNC.
- **Business model.** Delegated: optimise for the most power, freedom and leverage.
- **AI models.** Model-agnostic from day one. Every major provider is first-class and gets its own tuning.
- **Build, don't settle.** Build our own AI-native core rather than stacking on decades-old engines. Existing mature libraries are used only as reference oracles for testing.

## 1. Research findings (Sept 2026)

**Kernels.**
- **OCCT 8.0.1** (LGPL) is the only free exact B-rep kernel. It carries decades of design choices: global state, tolerance creep, no native provenance, and a heavy WASM build. Its fillets, shells and offsets are weak.
- **Parasolid** (Onshape, Shapr3D, Plasticity) is the gold standard: closed, with opaque pricing.
- **Every recent attempt at a new kernel has failed or stalled:**

| Project | Status |
|---|---|
| Fornjot | Archived in June 2026 |
| CADmium | Archived |
| truck | No fillet or shell yet |
| Zoo | Years of funded work; still cloud-only and closed |

  The lesson is that the difficulty sits in the long tail of geometric edge cases, not the volume of code. They lacked a verification machine; we build one first (§3b). This leaves an opening for a modern, open, AI-native kernel.

**AI for CAD.**
- The field has converged on **code-as-CAD on a real kernel inside a verify loop**.
- Direct neural B-rep generation is unshipped or low quality.
- Frontier models with a strong harness beat fine-tuned CAD models. On CADGenBench, Claude Opus 5 with a build123d-MCP harness leads at 0.677; the harness alone adds 0.10 and lifts validity from 88% to 100%.
- Editing an existing model is easier than generating one.

**Where AI still fails:**

| Task | Failure / success rate |
|---|---|
| Hardest text-to-CAD tier (Text2CAD-Bench L3) | ~70% doesn't even execute |
| Sweeps, lofts, shells | Fail 70–90% of the time |
| 6-DoF placement | Within 10 mm only 27.9% of the time |
| Assemblies | 30.6% match the intended design |

→ **The LLM never places anything by coordinates.** Constraint solvers handle sketches, mate solvers handle assemblies, and semantic references identify faces and edges.

**Proven reliability techniques:**

| Technique | Source | Measured effect |
|---|---|---|
| Clarify before modeling | ProCAD | — |
| Turn the spec into executable tests | CADTests | +10 points |
| Exact kernel metrics plus a *different* model judging multi-view renders | CADSmith | Chamfer error 28.4 → 0.74 |
| Renders tagged with face/edge IDs | Vision2CAD | — |
| Solver-status rewards | AutoConstrain | Fully constrained sketches 34% → 93% |
| Part-family skills | ArtisanCAD | — |
| Retrieve before generating | Leo AI | 60–80% of parts are duplicates |

**Platform precedent.**
- Plasticity: Electron + TypeScript + a native kernel addon, built by one developer.
- Figma: a compiled engine in WASM rendering through WebGPU.
- Zoo: cloud-only GPU kernel, so no offline use and a server cost for every session.
- Onshape: server-side kernel with a thin client.

## 2. Strategic decisions

**P0: Own the core; borrow only as oracles.**
- Every component that decides quality is ours and designed for AI: kernel, solvers, tessellation, renderer, regeneration, naming, DSL, checks, and later SubD, HLR (hidden-line removal), FEA and CAM.
- Mature open-source libraries (OCCT, PlaneGCS, SolveSpace, OpenSubdiv, Manifold, CalculiX, Gmsh) run only in dev/CI as **reference oracles for differential testing**. They are never shipped.
- We deliberately reuse existing tech only where it doesn't define quality: UI framework (React), app shell (Electron), CRDT (Loro), LLMs, and the specs of standard file formats (we write our own readers and writers).

|---|---|---|

An open AI-native kernel attracts contributors, researchers and crowdfunding. Our moat is harness quality, the data flywheel, hosted models and speed. MPL is App Store–compatible. |
| D2 | **Languages by purpose.** <br>• **Rust** for the whole engine ("Forge": kernel, solvers, tessellation, regeneration, renderer, I/O, checks). It gives memory safety, rayon parallelism and wgpu, and its compiler is an excellent verifier for coding agents. <br>• **TypeScript** for UI, DocStore, CadScript compiler, agent orchestrator, LLM gateway and MCP server. <br>• **Python** for ML, datasets and the OCCT/build123d oracle harness. <br>• **Swift** for the iPad host later. | Each language is used where it is strongest. |

Kernel indices are never persisted. | This fixes the hardest problem in parametric CAD at the root, and it doubles as the reference language an LLM needs. |

| D11 | **Freeform is native to Forge.** SubD cages evaluate to exact Catmull–Clark limit surfaces, exact B-splines in regular regions and certified fits near extraordinary vertices. ## 3. Core architecture

```
┌──────────────────────── Electron (desktop) / Browser (web) ────────────────────────────────┐
│ UI (React): viewport · timeline · sketcher · params · code view (Monaco+CadScript) · chat  │
│ forge-render (Rust→WASM, WebGPU; WebGL2 fallback) on canvas   DocStore (IR txns → Loro)     │
│ forge-solve (WASM) for 60 fps interactive sketch drag                                      │
│     │ IR snapshot ▼                          ▲ meshes, provenance names, diagnostics         │
│ Forge engine: native via napi-rs in an Electron utility process (multithreaded)             │
│              | WASM in a worker on web/iPad | native in CLI & cloud workers                 │
│   forge-regen (IR eval, expressions, queries, cache) → forge-ops/ssi/core → forge-mesh      │
│   forge-check (validity, DFM, mass, distance, interference) · forge-io (STEP/3MF/STL/…)     │
│ Agent runtime (utility process): orchestrator · LLM gateway · tool registry                 │
│ MCP server (localhost): same tool registry, for Claude Code / Cursor / other agents          │
└────────────────────────────────────────────────────────────────────────────────────────────┘
 CLI `acad` (native Forge): headless regen / export / render / eval, the harness for coding agents & CI
 oracle/ (Python + OCP/build123d, CI only): evaluates the same IR with OCCT for differential testing
```

### One command API, four clients
- The UI, the in-app agent, CLI/CadScript and the MCP server all call the same typed command layer.
- The same schemas generate the agent tool definitions and the MCP tools.
- The agent has no special privileges.

### IR essentials
**Document and features.**
- `Document { schema, units, params, parts, assemblies, blobs }`
- `Feature { id (uuidv7), name (= CadScript const), type, v (pinned behavior version), suppressed?, note?, expect? (verify clause), author, intent?, assumptions?, decision_ids?, …fields }`

**Feature types.**
- **v1:** sketch, extrude, revolve, hole (simple, counterbore, countersink, cosmetic-threaded, heat-set insert), fillet, chamfer, shell, draft, pattern (linear, circular, mirror), boolean, datums, mate connector, tag, import, text emboss.
- **Later:** sweep, loft, thicken, sheet metal, subd, mesh, sdf, custom.

**References.**
- `Ref { kind, sel: QueryAST, card, fp? }` is stored in the file.
- Resolution goes through Forge's native provenance: exact provenance → fingerprint for splits → query filters → geometric match (warns with confidence and candidates) → error.
- A failed feature passes its input through, so every error shows in a single regeneration.

**Expressions.** Our own grammar with dimensional analysis, evaluated in Rust. Results are deterministic everywhere, and units are always explicit in the IR.

**Edits.**
- Edits are domain ops (`addFeature`, `setField`, `setParam`, `moveFeature`, `setRef`, …) grouped into transactions with inverses, which gives undo/redo.
- An agent turn is one labelled group ("Revert turn").
- A code edit compiles, is structurally diffed against the IR by feature name, then applied as granular ops.

**File format.**
- A zip containing `manifest.json`, a canonical `document.json`, `blobs/` and `cache/` (Forge-native B-rep, meshes and a thumbnail, keyed by the Forge build).
- A plain `.json` export for git and agents.

**Caching.**
- Chained per-feature keys: `k_i = H(k_{i-1}, type, v, evaluated fields, resolved refs, forgeBuild)`.
- An in-memory LRU of body states, plus a persistent B-rep and mesh cache.

### CadScript example: a maker part
```ts
import { param, sketch, rect, circle, extrude, hole, grid, fillet, shell, edgesBetween, XY, Z } from "@acad/std";
const width = param(80), depth = param(50), thick = param(8);
const screw = param(5.5, { note: "M5 clearance" });
const base   = sketch(XY, { outline: rect({ center: [0, 0], w: width, h: depth }) });
const plate  = extrude(base, { distance: thick });
const bossSk = sketch(plate.cap("end"), { ring: circle({ center: [0, 0], d: 22 }) });
const boss   = extrude(bossSk, { distance: 12, op: "join" });
const mounts = hole(plate.cap("end"), { at: grid({ nx: 2, ny: 2, dx: width - 12, dy: depth - 12 }),
                                        d: screw, depth: "through", counterbore: { d: 10, depth: 3 } });
const corners  = fillet(plate.sides().edges().parallel(Z), { r: 4 });
const bossRoot = fillet(edgesBetween(boss.sides(), plate.cap("end")), { r: 2 });
const hollow = shell(plate, { open: [plate.cap("start")], thickness: 2, expect: { solids: 1, minWall: 1.9 } });
```
Diagnostics come from Forge's explainable operations, for example:
```
error FILLET_FAILED "corners": 1/4 edges failed: max feasible r = 3.41 (adjacent face width 6.82); hint: reduce r or move 'corners' before 'mounts'
```

### 3b. Forge: the AI-native kernel

**Crates in the `forge/` Cargo workspace:**

| Crate | Contents |
|---|---|
| `forge-core` | Half-edge B-rep topology with native provenance, stored in arenas with typed generational indices (no pointer graphs). All numeric code is generic over a `Scalar` trait (f64 / Interval / Dual / Rational). Critical predicates and invariants are verified with Kani/Verus. Geometry: analytic curves and surfaces (line, circle, ellipse, plane, cylinder, cone, sphere, torus), linear-extrusion and revolution surfaces, B-spline/NURBS curves and surfaces. Robust numerics: Shewchuk-style adaptive exact predicates, interval arithmetic, exact rationals for analytic cases. |
| `forge-ssi` | Surface–surface and curve–surface intersection. Closed-form solutions for analytic pairs. Certified marching (interval-verified) with B-spline fitting of the intersection curve for the general case. Tangency and degeneracy classification. |
| `forge-ops` | Planar regions from sketches, extrude, revolve, booleans (fuse, cut, common, split), fillet and chamfer (rolling-ball blends; analytic where possible, NURBS blends otherwise; vertex blends and setbacks), shell and offset, draft, patterns, transforms. Later: sweep, loft, thicken, variable blends, sheet metal. |
| `forge-mesh` | Watertight B-rep-aware tessellation, mesh bodies, SubD (Catmull–Clark limit evaluation), SDF/implicit, and mesh↔B-rep bridges. |
| `forge-solve` | Sketch and assembly solvers (D8). |
| `forge-regen` | IR evaluation, expressions, query engine, caching. |
| `forge-check` | Validity, mass properties, distance and clearance, interference, DFM analyses (overhang, wall thickness via distance fields, minimum feature size, sharp internal corners for CNC). |
| `forge-io` | Our own STEP AP214/242 reader and writer, 3MF, STL, OBJ, glTF, DXF/SVG. Later: hidden-line removal (HLR) for drawings. |
| `forge-render` | The wgpu renderer (D7). |
| `forge-napi`, `forge-wasm`, `forge-ffi` | Bindings for Node/Electron, the web, and Swift/iPad. |

**What makes Forge AI-native** (things legacy kernels can't retrofit):
1. **Native provenance and naming** on every entity, which fixes topological naming at the root.
2. **Explainable operations.** Every failure returns a structured cause and the feasible parameter range, computed analytically where possible.
3. **Bit-identical determinism** across macOS, Windows, Linux and WASM. No nondeterministic parallelism affects results.
4. **Exact-first numerics** for analytic geometry (most maker and CNC parts), and certified, tolerance-aware handling elsewhere. Tolerances are explicit per entity and never creep silently.
5. **Query-native.** Semantic selectors are evaluated inside the kernel.
6. **Differentiable evaluation** (F4). Gradients of volume, mass, distances and clearances with respect to parameters. This enables "make it 20% lighter" requests, optimization, and exact RL rewards.
7. **Convergent representations.** B-rep, SubD, mesh and SDF live in one kernel.
8. **Performance by design.** Data-oriented storage, SIMD, rayon parallelism outside the deterministic path, and GPU compute later.

**The verification machine is built before the features:**
- **Differential testing against OCCT.** The `oracle/` harness (Python OCP/build123d) evaluates the same IR and we compare volume, area, topology counts, validity and Hausdorff distance.
  - It covers our corpus plus about 178k DeepCAD sketch-and-extrude programs, Fusion 360 Gallery reconstruction sequences, and ABC STEP models (1M) for import, tessellation and mass-property checks.
  - Every dataset licence is checked before use.
- **Property and fuzz testing:** random feature programs, random perturbations, and near-degenerate generators (tangent, coincident and sliver cases).
- **Invariants checked after every operation:** Euler characteristic, closed shells, orientation, no self-intersection, provenance completeness.
- **A "failure zoo."** Every bug becomes a permanent regression case.
- **Explicit failure policy:** Forge fails loudly with a diagnostic and never silently returns wrong geometry. Silent-wrong results measured by the oracle must be 0 to pass a release gate.

**Milestones.** Each milestone is gated by oracle comparison and the robustness corpus:

| # | When | Scope | Gate |
|---|---|---|---|
| **F0** | M1–M2 | Topology and provenance, analytic and B-spline curves, analytic surfaces, exact predicates, planar regions, extrude and revolve (spline profiles included), tessellation, mass properties, STL/3MF export, the oracle harness | Bit-identical on all four targets; matches the oracle on 1k extrude/revolve programs |
| **F1** | M2–M5 | SSI (surface–surface intersection) for analytic pairs plus certified marching, booleans, holes, patterns, mirror, STEP export, STEP import (analytic + B-spline) | ≥99.5% agreement with the oracle on DeepCAD replays; fewer failures than OCCT; 0 silent-wrong results |
| **F2** | M4–M8 | Fillet and chamfer, shell and offset, draft, healing, text emboss | **Maker release gate.** Validity ≥ OCCT on the 300-case fillet/chamfer/shell corpus and the maker corpus; provenance survival ≥99% |
| **F3** | M8–M14 | Full NURBS surfacing: sweep, loft, general and variable blends, NURBS offsets, HLR for drawings, sheet-metal operations | |
| **F4** | M12–M18 | Differentiable evaluation; native SubD, mesh and SDF (convergent modeling) | |
| **F5** | M18+ | GPU compute (tessellation, analysis, batch evaluation for agents); `forge-sim`, a differentiable FEA validated against CalculiX; CAM toolpaths | |

## 4. AI agent system

### Roles
The eval harness chooses a model for each role, per provider profile.

| Role | Capability needed | Anthropic default | Other providers |
|---|---|---|---|
| Triage / utility | Small, fast | Haiku 4.5 | GPT/Gemini small tiers, local |
| **Designer** (main loop: clarify, plan, build, repair) | Frontier agentic | Opus 5.5 (medium effort; high for planning and repair) | GPT-5.x / Gemini 3.x flagships, ranked by MakerBench |
| Spec + test writer | Frontier; fresh-context sub-agent that **never sees the builder's transcript** | Opus 5.5 (high) | Same |
| Critic / judge | Top vision model, **from a different model family than the designer** | Fable 5.1 (Opus 5.5 for zero-data-retention tiers) | Swap families across providers |
| Engineer advisor | Frontier, with the calculation tools | Opus 5.5 | Same |
| Economy main loop | Mid tier | Sonnet 5 | Mid tiers |

Rules for the main loop:
- Use one model per task, because caches are per model. Cheaper models run only as sub-agents.
- Keep history append-only. Use `tool_choice: auto` with strict schemas (some models reject forced tool use).
- Handle refusals explicitly.

### Orchestrator
Our own TypeScript state machine on top of the gateway, not the Claude Agent SDK. It runs the same way in:
- the Electron utility process
- headless Node (evals, CLI)
- a browser worker
- the server

The Agent SDK is still used in the "external agent" eval track, driving our MCP server.

### Loop
```
TRIAGE ─┬─ ASK/EXPLAIN (read-only) ──────────────────────────────────────────► DONE
        ├─ QUICK_EDIT: plan-lite → BUILD → VERIFY L0–L3 → PROPOSE
        └─ DESIGN: CLARIFY (≤1 round, ≤3 multiple-choice Qs with defaults)
                 → SPEC (DesignSpec + CADTests, FROZEN) → RETRIEVE (library → skill → std part → generate)
                 → PLAN (feature plan, or product-structure tree for assemblies)
                 → per step: ACT (1–3 features) → REGEN → L0–L2 ; fail → REPAIR ×2 → ROLLBACK+REPLAN ×1 → ASK_USER
                 → MILESTONE: L3 tests → L4 DFM/eng → L5 judge ; fail → REFINE ×2 → PROPOSE with known issues
                 → PROPOSE (draft-branch diff) → per-feature accept/reject → COMMIT + decision log
Every transition: budget and interrupt checks. A user edit in the agent's scope pauses it, and it rebases.
```
Tests are frozen. The builder can only *propose* a test change.

### Context
- **Stable, sorted prefix:** tools, role prompt, a DSL reference of about 6k tokens, project conventions. Then a cache breakpoint.
- **Rare tools** are deferred behind tool search.
- **Mutation results** come back as short deltas. The IR summary (≤4k tokens) is only sent at step boundaries.
- **Assemblies:** only the part in focus is expanded. Other parts appear as cards of about 100 tokens (ports, envelope, mass).
- **Selection** is described semantically, with an image crop when needed.
- **Images:** at most 4 kept live.
- **Task size:** about 40 turns or 150k tokens. Longer work is split along the product-structure tree and handed off through memory files.

### Tools
Every tool result is ≤~2k tokens, names entities by ID and tag, and returns **actionable errors from operation playbooks** built on Forge's explainable diagnostics.

| Group | Tools |
|---|---|
| **Control** | `ask_user`, `report_progress`, `propose`, `load_skill`, `search_tools` |
| **Editing** (agent-branch transactions) | `apply_dsl`, `sketch_edit` (returns solver status, DOF and conflicts), `auto_constrain`, `set_param`, `edit_feature`, `tag`, `suppress`/`delete`/`reorder` (need approval on user features), `instantiate_skill`, `insert_standard_part`, `define_part`/`define_port`/`mate` (Phase 2), `checkpoint`/`rollback` |
| **Inspection** | `ir_summary`, `get_code`, `get_selection`, `query` (checks uniqueness), `describe`, `measure`, `mass_props`, `bbox`, `section`, `min_wall`, `clearance`, `interference`, `diff` |
| **Rendering** | `render(views, overlay: face_ids/edge_ids, highlight, section)`, `render_diff`, `render_sketch` (colored by DOF) |
| **Verification** | `run_tests` (reports margins), `validate`, `dfm(process, profile)`, `request_review`, `propose_test_change` |
| **Knowledge** | `search_parts` (text and shape embeddings), `search_standard_parts`, `search_skills`, `reference(topic)` (curated, cited engineering handbook), `memory_read`, `log_decision` |
| **Engineering calcs** (deterministic; each returns formula, inputs and source) | `fit` (ISO 286), `fastener`, `print_clearance`, `beam_plate`, `snap_fit`, `gear`, `bearing_select`, `material`; later `optimize` (Forge gradients) and `fea_run` (as an MCP Task) |
| **Manufacturing** | `export` (needs approval), `print_orientation`, `slicer_handoff`; later `drawing`, `bom` |

### Verification ladder
Checks run cheapest first. A level runs only if the one below it passes.

| Level | Checks |
|---|---|
| L0 static | Types, schema, units, parameter ranges, selector cardinality |
| L1 kernel | Regeneration succeeds, Forge invariants, closed solids, body count, sketch DOF |
| L2 per-op | `expect` clauses and skill rules |
| L3 CADTests | Spec tests, regression tests, tag survival, and an **editability probe** (vary parameters ±20%) |
| L4 | DFM and engineering checks |
| L5 visual judge | 6 ID-tagged views plus the spec and metrics (~$0.14) |
| L6 | Human reviews the diff |

### Ask and stop rules
**Ask before modeling** only if both are true:
- The ambiguity changes topology or interfaces, the units are unclear, or requirements conflict.
- There is no safe default.

Otherwise, each assumption becomes an editable **parameter chip**.

**Stop when:**
- 2 repairs plus 1 replan have failed
- the same error repeats
- 80% of the budget is spent (show a summary and ask "continue for ~$X?")
- the tests pass but the judge disagrees
- the next step would touch user-authored features or anything outside the selection
- the part is safety-critical (warn and require acknowledgment)
- a policy refusal happens (never retry around it)

### Cost targets
Anthropic default profile; output tokens dominate.

| Tier | Median | Cap |
|---|---|---|
| Q&A | $0.03 | $0.15 |
| Quick edit | $0.15 | $0.50 |
| T1 part | $0.75 | $1.50 |
| T2 part | $2.50 | $6 |
| T3 assembly | $10 | $20, with approval gates |

Economy mode costs about 45% less. Single-turn eval and judge calls use batch APIs.

### Scaling to machinery
**Product-structure tree first.** Each node records function, process, envelope, mass target and **typed ports**: bolt pattern, shaft/bore, planar mount, rail, gear mesh, PCB footprint.
- Ports are IR objects. Mates connect ports, and the solver places parts.
- A **skeleton part** owns every dimension that crosses parts. Parts may only reference skeleton parameters and ports.
- Each part is its own task with its own spec and tests.
- Build order: skeleton → interfaces → standard parts → custom parts → integration tests (interference, clearance, DOF/motion, BOM, mass).

**Part-family skills** live in `skills/<family>/` as `SKILL.md`, `params.ts`, `template.cad.ts`, `verify.ts` and `examples/`.
- A skill expands into ordinary features the user can edit.
- The community contributes skills, and CI tests each one.
- Phase 1 ships 25 families:
  - brackets, gussets, hole-pattern plates, standoffs
  - PCB enclosures (screw, snap and slide lids), clips, knobs
  - print-in-place hinges, snap fits, living hinges
  - Gridfinity bins and baseplates, Skadis hooks, wall mounts
  - NEMA17 mounts, 2020-extrusion brackets, GT2 pulleys, spur gears, couplers, pillow blocks
  - threaded caps, handles, drawers

**Standard parts** are TypeScript/Rust generators, each with ports:
- screws (ISO 4762, 7380, 10642), nuts (ISO 4032), washers, heat-set inserts
- threads (cosmetic or modeled)
- bearings (608, 6xx, LM8UU)
- NEMA 14/17 motors, 2020/2040 extrusion profiles, servos
- Raspberry Pi, Arduino and ESP32 mounting patterns
- TraceParts later

**Project memory** (git-friendly):
- `design/spec.md`: requirements, with IDs
- `design/decisions.jsonl`
- `design/tests/*.test.ts`
- `project.conventions.md`

Features carry `intent`, `assumptions` and `decision_ids`, so hovering over a value like "why 3.6 mm?" shows decision D-017.

## 5. AI + manual co-editing UX
- **Selection-aware chat.** `@` mentions and a selection chip. "Make this thicker" resolves to the parameter that drives it.
- **Draft branch and diff.** A ghost overlay in the viewport and badges in the timeline.
  - **Accept, Reject or Edit each feature.** Rejecting is dependency-aware.
  - The CadScript diff is shown alongside.
  - The whole task is one undo step.
- **Live progress.** A plan checklist, CadScript streaming into the code view, a cost meter and a Stop button. First geometry appears within about 20 s.
- **Assumptions as chips** (e.g. "PLA · 0.4 nozzle · M3 · 0.2 clearance"). Editing a chip regenerates **with no LLM call**.
- **Spec card** for T2 parts and up, editable before the build starts.
- **Design Review mode.** Pinned findings, each with Why (rule or calculation plus source), Fix (the agent drafts a branch) and Dismiss.
- **Always-on checks with no LLM:** overhang heatmap, thin walls, bridges, sharp internal corners (CNC), unconstrained sketches.
- **Learned preferences** are offered as updates to project conventions, never applied silently.

## 6. Evaluation harness and data flywheel (built in week 1)

### Evaluation harness
Runs headless (native Forge, offscreen `forge-render`, the agent).

**MakerBench:** 60 tasks in Phase 0, 300 by beta, 600 by v1.0.
- Tiers:
  - T1: simple parts
  - T2: multi-feature parts
  - T3: assemblies
  - T4: edits
  - T5: under-specified prompts (does it ask or assume well?)
  - T6: image or sketch to part
- Each task has a reference model, **hidden tests**, a process profile and tags.
- Sources: hand-written tasks, verified synthetic variants, near-miss edits, and later community submissions.

**External benchmarks:** CADPrompt, a Text2CAD-Bench subset, CADGenBench generation and editing tasks. Check each licence, and never use them as prompt examples.

**Metrics:**
- validity; hidden-test pass rate; IoU and Chamfer distance; spec adherence
- editability (perturbation survival, share of sketches fully constrained, magic-number count)
- edit locality; judge agreement with humans
- $/task, p50/p90 latency, repair count, quality of clarifying questions
- live product: accept rate, manual corrections within 10 minutes, re-prompts

A **cross-provider leaderboard** decides routing and tuning.

**CI:**

| Trigger | What runs |
|---|---|
| Every PR | Unit tests, **Forge oracle diffs** (sampled), trajectory replay |
| Prompt, tool or skill PRs | 25 live tasks |
| Nightly | 100 tasks plus the full Forge differential suite |
| Weekly | Full suite at pass@3 across providers |

- **Merge gate:** block if any tier drops more than 3 points, cost rises more than 15%, or any silent-wrong Forge result appears.
- **Budget:** about $1–2k per month for evals, plus CI compute for the oracle.

### Data flywheel
Opt-in, with separate switches. Off for BYO-key users and private projects.

**Logged:**
- trajectories and verifier results
- accept/reject decisions per feature
- **manual edits made after accepting** (gold data)
- dismissed findings
- sketches with their final constraints
- Forge failures together with the fix that worked, which feed the failure zoo

**Model roadmap:**

| When | Step |
|---|---|
| M1–12 | No fine-tuning. Mine failures weekly into repair hints, skill rules and DSL ergonomics. |
| Phase 3 | A small local ONNX sketch auto-constrain model, rewarded by solver status. |
| Phase 4 | A distilled vision critic that handles about 80% of judge calls. |
| Phase 5–6 | Mesh, image or point cloud → CadScript: SFT on synthetic programs, then online RL with IoU, validity and editability rewards, plus **Forge-gradient rewards**. Hosted "STL remix → parametric". |
| Later | Publish MakerBench and the Forge RL environment openly. |

  - Prompts: `design-part`, `review-design`.

- **CLI:** CadScript files in git plus `acad build | test | render | export`, with GUI live-reload.

## 8. Roadmap
M1 = Oct 2026. Parallel agent workstreams (Forge, app, agent, evals) run in separate worktrees. **Exit gates decide when a phase ends, not dates.** Building Forge first moves the public MVP about 3 months later than an OCCT-based plan would, in exchange for a kernel we own.

### Phase 0: Foundations and spikes (M1–M2)
Every spike is go/no-go.

1. **Forge F0 core + oracle harness.**
   - Bit-identical output on macOS, Windows, Linux and WASM.
   - Extrude and revolve match the OCCT oracle on 1k programs.
   - napi and WASM builds both work in the CLI and in Electron.
2. **Native provenance naming harness.** 12–20 maker models, 10 scripted mutations each.
   - ≥97% correct on dimension and suppress edits.
   - ≥90% correct on topology-changing edits.
   - **100% of fallbacks flagged.**
3. **SSI + boolean feasibility.** Certified intersection for plane/cylinder/cone/sphere/torus pairs, and booleans on 500 DeepCAD replays.
   - ≥99% agreement with the oracle.
   - 0 silent-wrong results.
   - This sets the pace for F1.
4. **forge-solve sketch solver.** 60–200-entity sketches.
   - ≤4 ms per drag frame (WASM).
   - DOF counts, redundancy and minimal conflict sets match PlaneGCS/SolveSpace on 1k generated sketches.
5. **forge-render in Electron.**
   - Exact edges and silhouettes.
   - Pixel-exact ID picking.
   - Section view.
   - WebGL2 fallback works on Linux.
   - A dimension edit shows up in 3D within ≤150 ms.
6. **CadScript ⇄ IR round-trip.** Lossless on 50 models (property tests). UI edits keep comments and formatting.
7. **Agent vertical slice + bake-off.** About 12 tools. Anthropic, OpenAI and Google flagships, CadScript vs build123d-MCP, on 30 T1 tasks.
   - Early runs can evaluate CadScript through the `oracle/` backend, so agent work isn't blocked by Forge.
   - Pass: ≥ build123d's score minus 5 points, ≥50% of hidden tests passing, median cost ≤$1.
8. **Eval harness skeleton plus 60 MakerBench tasks.**

**Deliverables:** architecture decision records (ADRs), a decision memo, a landing page and waitlist, and a public "building an AI-native kernel" dev log.

### Phase 1: Maker MVP on Forge (M2–M10)
- Closed alpha when the **F2 gate** passes (target ~M7).
- **Open-source public alpha ~M8.**
- Beta ~M10.

**In scope:**
- **Documents:** single-part documents with multiple bodies.
- **Sketcher:** line, arc, circle, rectangle, slot, polygon, spline, constraints and dimensions.
- **Features:** extrude, revolve, holes, fillet, chamfer, shell, draft, patterns, mirror, booleans, datums, text emboss.
- **Parametrics:** parameters and equations, the timeline, a two-way code view.
- **Import and export:**
  - STL and 3MF imported as reference meshes; STEP imported as a solid.
  - STL, 3MF and STEP export.
- **Printing:** FDM checks, orientation suggestions, printer profiles.
- **AI:**
  - The full agent loop with 25 skills and the standard-parts set.
  - Draft-branch diffs.
  - BYO keys for every provider at alpha; hosted credits at beta.
- **Integration and distribution:**
  - MCP server and CLI.
  - Signed macOS and Windows builds with auto-update; Linux AppImage beta.
  - A web preview build is optional and cheap, since Forge and the renderer are WASM-native.

**Deferred:** assemblies, sweeps and lofts, drawings, sheet metal, cloud (billing only), FEA, CAM, SubD, iPad, fine-tuning, a plugin API (skills only).

**Exit gates:**
- Accuracy: T1 ≥85% hidden-test pass@1; T2 ≥65%; T4 ≥80%.
- Robustness: validity ≥98%; editability ≥90%; ≥99% of provenance names survive edits; 0 silent-wrong Forge results in the nightly differential suite.
- Speed and cost: median T1 ≤$0.75 and ≤90 s.
- Adoption and quality: 20 alpha makers each print ≥3 parts; ≥60% of proposals accepted with ≤2 manual edits; ≥99.5% crash-free sessions; 300 weekly active users.

### Phase 2: Assemblies + v1.0 (M10–M15)
**In scope:**
- **Assembly modeling:** assemblies with ports; 6 mate types via `forge-solve`; a skeleton part; interference checks; motion scrubbing; BOM.
- **AI:** product-structure decomposition, with a task per part and automatic mating of standard parts.
- **Geometry:** sweeps, lofts and splines (F3 begins; exposed through skills first).
- **Output and publishing:** slicer handoff (Bambu, Orca, Prusa); publish pages with parameter sliders.
- **Evaluation:** CADGenBench.

**Exit gates:**
- Assembly quality: T3 ≥60% intent-correct (baseline 30.6%); 0 coordinate placements (enforced by a linter); ≥95% of accepted assemblies interference-free.
- Performance: a 50-part assembly regenerates in <3 s.
- Business: v1.0 shipped, 2k weekly active users, $5k MRR.

### Phase 3: Fabrication (M14–M19)
**In scope:**
- **Sheet metal:** flanges, bends, reliefs, K-factor, flat patterns → DXF.
- **Laser:** DXF/SVG export.
- **Drawings:**
  - Forge HLR views.
  - **Auto-dimensioning driven by the design's parameters.**
  - Sections, detail views, title block.
  - GD&T is *suggested* from ports, never applied automatically.
  - A vision-model review pass.
- **CNC:** 3-axis manufacturability checks.
- **AI:** the auto-constrain model.

**Exit gates:**
- Drawings:
  - Auto-drawings produced for 90% of MakerBench parts.
  - Average rating ≥4/5 on a 50-part sample.
- Sheet metal: flat patterns within ±0.1 mm on 20 parts.
- Auto-constrain: ≥85% of sketches end up fully constrained.
- Business: 5 paying shops.

### Phase 4: Web + cloud (M17–M22)
**In scope:**
- **Web:** a web build with OPFS storage.
- **Accounts and sharing:** accounts and sync; share, fork and branch/merge via IR diffs; geometry-anchored comments.
- **Cloud agent:** hosted long agent tasks.
- **Community:**
  - Public customizer pages with real B-rep and STEP. This is the viral loop, competing with Thingiverse and MakerWorld customizers.
  - A community library of skills and parts.
  - TraceParts integration.
- **AI:** the distilled critic.

**Exit gates:**
- Web parity: ≥90% of part-design features work in the browser; P95 load of a 30-feature part in <5 s.
- Business: 4k monthly active users, $15k MRR.
- Judge cost: down 60% with at most a 2-point quality loss.

### Phase 5: Organic + simulation (M20–M26)
**In scope:**
- **Freeform modeling:** the SubD workspace on Forge F4 (creases, symmetry, dimensionable cages); SubD → B-rep with CAD features applied afterwards; SDF/implicit bodies (lattices, organic blends).
- **Optimization:** differentiable "optimize" tools.
- **AI meshes:** TRELLIS.2 used as a reference body.
- **Simulation:** `forge-sim` linear static FEA, validated against CalculiX, with loads on semantic faces. The advisor explains the margins.

**Exit gates:**
- SubD → B-rep: ≥90% success on cages up to 2k faces.
- FEA: within ±10% of the oracle on 15 cases.
- Advisor: catches ≥80% of under-designed brackets.

### Phase 6+
- Scan, mesh or photo → parametric model (fine-tuning + RL with Forge gradients).
- 2.5D CAM and laser toolpaths (our own; Kiri:Moto as the oracle).
- iPad: native Swift host with Forge FFI, `forge-render` on Metal via wgpu, and Pencil support.
- Real-time collaboration (Loro + a Rust relay).
- PDM/PLM.
- GPU Forge compute.
- Forge OEM licensing.

### Explicitly reused (not built)
React, Electron, Loro, the LLMs, and file-format *specs*. Everything that defines quality is ours.

## 10. Top risks and mitigations
| Risk | Mitigation |
|---|---|
| **Forge's long tail** (the thing that sank Fornjot and slowed Zoo) | The verification machine comes first: large-scale oracle differential testing (DeepCAD, Fusion 360 Gallery, ABC, our corpus), fuzzing, invariants, and a failure zoo. Exact predicates and certified intersection. Explainable failures, never silent. Milestones ordered from winnable cases outward (analytic → B-spline → general NURBS). Release gates are measured against OCCT. Many agent workstreams run in parallel. |
| MVP is later than the OCCT path (~+3 months) | Agent, app and eval work proceeds in parallel against the `oracle/` backend and the growing Forge. Public alpha is gated on F2, not on a date. |
| Topological naming instability | Native provenance plus queries and tags; a harness in Phase 0; never resolve silently; a repair UI. |
| LLMs weaker at CadScript than build123d | Phase 0 bake-off; change the syntax, not the engine. |
| Agent cost and latency | Tiered pipeline; deterministic checks before any LLM call; caching; economy mode; judge distillation. |
| WASM memory limits (no Memory64 on iOS) | Native napi and FFI paths; data-oriented memory; iPad through the native Swift host. |
| Scope creep | Phase exit gates, the list of explicitly reused components, skills instead of a plugin API. |
| Provider drift | Per-model profiles plus a nightly cross-provider leaderboard; routing is config, not code. |

## 11. What happens right after approval (start of Phase 0)
1. **Initialise the repo.**
   - `git init`, a Cargo workspace `forge/`, and pnpm + Turborepo `packages/`.
   - Python `oracle/` and `ml/` (uv).
   - CI for build, test, clippy, lint and a licence check.
   - MPL-2.0 and Apache-2.0 licence files per package, plus a CLA bot.
2. **Write the foundational documents.**
   - `docs/VISION.md`, `docs/ARCHITECTURE.md` (§2–4), `docs/ROADMAP.md`.
   - `docs/adr/0000-own-the-core.md` and `0001–0011` (D1–D11).
   - `docs/FORGE.md` (§3b: kernel design, numerics policy, verification machine).
   - `docs/RESEARCH.md` (findings and sources).
   - A root `CLAUDE.md`/`AGENTS.md`: conventions, commands, "verify with the CLI and oracle", package boundaries.
3. **Build the verification machine first.**
   - `oracle/`: an IR evaluator on OCP/build123d.
   - `kernel-diff` runner and the corpus format.
   - DeepCAD and Fusion 360 Gallery importers into the IR, after checking their licences.
4. **Forge F0.** `forge-core` (topology + provenance, geometry, exact predicates), then regions, extrude and revolve, tessellation, mass properties, STL/3MF, and the `acad` CLI. Tested against the oracle from the first commit.
5. **Spikes 2–8** run in parallel worktrees. Each produces a go/no-go report in `docs/spikes/`.
6. **Record the owner's standing preferences** for coding agents: product owner, agents write all the code, model-agnostic, desktop-first, makers first, **own the core / oracles only**.

## 12. Verification
- **Forge:**
  - Nightly differential suite against OCCT (volume, area, topology, validity, Hausdorff distance), with 0 silent-wrong results.
  - Invariants checked after every operation, property and fuzz tests, a bit-identical cross-target check, and benchmarks under `forge/benches`.
- **App:**
  - Vitest unit and property tests (IR ops and their inverses, CadScript round-trip, units).
  - Golden-geometry corpus tests.
  - Playwright-Electron end-to-end tests (sketch → extrude → fillet → export).
  - `acad` headless regeneration and export of every corpus model.
- **AI:** MakerBench plus external subsets through `evals`. Trajectory replay runs on every PR, live suites nightly and weekly, and the cross-provider leaderboard feeds the phase exit metrics.
- **Manual:** in the Electron app, ask the agent for "a Gridfinity 2×3 bin with label tab", review the draft diff, accept it, export 3MF, slice and print.
